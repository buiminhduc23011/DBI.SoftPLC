# ADR-002: Tag Table là nguồn sự thật, sinh `IO.g.cs`

**Date:** 2026-07-26 | **Status:** ✅ Accepted

## Context

TIA Portal quy định tag phải khai báo trong **PLC tags / Default tag table** trước khi dùng trong khối chương trình. Studio hiện làm ngược: code viết `IO.StartButton` tự do rồi mới map thủ công ở bảng Tag Mapper (dữ liệu hardcode trong [MainViewModel.cs:69-75](../../../src/DBI.Controller.Studio/ViewModels/MainViewModel.cs)).

Vấn đề nằm ở [IOContainer.cs](../../../src/DBI.Controller.SDK/IO/IOContainer.cs) — nó là `DynamicObject`:

```csharp
public override bool TryGetMember(GetMemberBinder binder, out object? result) {
    result = _memoryImage.GetBool(binder.Name);   // luôn bool, bất kể kiểu tag
    return true;                                   // luôn thành công, kể cả tag không tồn tại
}
```

Hệ quả: `IO.StartButtonn` (thừa chữ n) **compile pass** và trả `false` âm thầm. Trong điều khiển máy móc đây là loại lỗi nguy hiểm nhất — nút Start không bao giờ tác dụng, không có thông báo lỗi nào.

## Decision

**Tag Table là nguồn sự thật duy nhất. Studio sinh `Generated/IO.g.cs` từ bảng.**

1. `IOContainer` **bỏ** kế thừa `DynamicObject`, trở thành `public partial class`.
2. Giữ `GetBool/SetBool/GetInt/SetInt/GetFloat/SetFloat` + indexer làm **API nội bộ** cho code sinh gọi.
3. `ControllerProgram.IO` đổi kiểu từ `dynamic` sang `IOContainer`.
4. Mỗi dòng Tag Table sinh một property strongly-typed:

```csharp
// <auto-generated>  Generated/IO.g.cs
//   Sinh bởi DBI.Studio từ Tag Table. KHÔNG SỬA TAY.
// </auto-generated>
public partial class IOContainer {
    public bool  StartButton => GetBool("StartButton");                                  // Input  → read-only
    public bool  ConveyorRun { get => GetBool("ConveyorRun"); set => SetBool("ConveyorRun", value); }  // Output
    public float Temperature => GetFloat("Temperature");
}
```

5. **Direction quyết định accessor:** `Input` → chỉ `get`; `Output` → `get`+`set`; `Memory` → `get`+`set`.
6. Tag trỏ **trực tiếp** tới `(Device, Address)` — không có tầng địa chỉ `%I0.0` trung gian (xem Constraint C-4).

## Consequences

### Tích cực
- **IntelliSense khả thi** — điều kiện tiên quyết cho phase-08
- Sai chính tả tag = **lỗi compile**, không còn im lặng
- Kiểu dữ liệu được kiểm tra tại compile time; hết bug "đọc Real trả về bool"
- Ghi vào tag Input = lỗi compile (không có setter) — đúng ngữ nghĩa PLC
- Đổi địa chỉ phần cứng chỉ sửa bảng, code logic không đụng tới

### Tiêu cực / chi phí
- Thêm bước generate trước mỗi lần compile
- **Breaking change** cho mọi code đang dùng `dynamic IO`: [ControllerProgram.cs:16](../../../src/DBI.Controller.SDK/ControllerProgram.cs), `Sample.Conveyor`, `DBI.Controller.Tests`
- Không thể tạo tag động lúc runtime (chấp nhận được — PLC không làm vậy)
- `Generated/` phải được bảo vệ khỏi sửa tay (đặt read-only trong editor + header cảnh báo)

### Việc bắt buộc kéo theo
- Sửa `IOContainer`, `ControllerProgram`, `Sample.Conveyor`, tests — **phase-00**
- Chuẩn hoá key: `MemorySnapshot` dùng `StringComparer.OrdinalIgnoreCase`, generator phải sinh tên hợp lệ C# và **cấm trùng tên khác hoa/thường**
- Validate tên tag là C# identifier hợp lệ, không trùng từ khoá

## Phương án bị loại

**Code trước, map sau** — giữ `dynamic`. Loại vì giết IntelliSense và để lọt lỗi chính tả.

**Hai chiều (bi-directional sync)** — mạnh nhất nhưng cần Roslyn analyzer quét ngược code + xử lý xung đột. Ghi vào Backlog, có thể làm sau khi phase-08 đã có Roslyn workspace sẵn.
